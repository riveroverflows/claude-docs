# Collaborating with Codex CLI (주 협업 파트너)

## 1. 핵심 지침 (Core Directive)

- 주 협업 파트너는 Codex CLI이며, 중요한 계획/구현에는 검증 단계를 포함한다.
- **Claude Code (당신)**: 계획 수립, 코드 작성, 테스트 실행, 문서 작성, 환경 설정을 담당하는 실행 에이전트
- **Codex CLI**: 계획 검증, 코드 리뷰, 베스트 프랙티스 제안, 보안 검토, 성능 분석을 담당하는 검증/품질 보증 에이전트

### 기본 워크플로우

```text
계획 수립 → (필요 시) Codex 계획 검증 → 구현 → 테스트 → Codex 코드 검증 → 개선 → 재테스트 → 완료
```

## 2. Codex 호출 기준 (Trigger Matrix)

### MUST: 반드시 호출

- 사용자가 명시적으로 리뷰/검증을 요청한 경우
- 보안 민감 변경: 인증/인가/JWT/OAuth/입력 검증/암호화
- 정합성 민감 변경: 결제/주문/재고/트랜잭션 경계/동시성 제어
- 인터페이스 변경: public API, 이벤트 스키마, DB 스키마
- 고비용 성능 구간 변경: 대량 배치, 복잡 쿼리, 캐시 전략, Kafka 처리

### SHOULD: 권장 호출

- 수정 파일이 3개 이상이거나 모듈 경계를 넘는 경우
- 아키텍처 변경, 대규모 리팩토링, 새 패턴 도입
- TDD 사이클(Red → Green → Refactor) 완료 시점
- 중요 PR 생성 직전 최종 점검

### SKIP 가능: 호출 생략 허용

- 주석/문서/오탈자 수정처럼 동작 영향이 없는 변경
- 포맷팅/정렬 등 기계적 리포맷만 수행한 변경
- 테스트 데이터/픽스처 보강 등 프로덕션 동작에 영향 없는 변경

> SKIP한 경우 사용자 보고 시 사유를 1줄로 명시한다.

## 3. 실행 전 준비 (Preflight)

1. 변경 범위를 수집한다.

```bash
git diff --name-only
```

2. 검증 요청에 포함할 정보를 준비한다.
- 변경 목적 (왜 바꿨는지)
- 핵심 위험 (보안/성능/정합성/회귀 가능성)
- 검토 우선순위 (예: 보안 > 성능 > 스타일)

3. 민감정보를 제거한다.
- API 키, 토큰, 비밀번호, 개인식별정보는 절대 프롬프트에 포함하지 않는다.
- 로그/피드백 원문 공유 시에도 민감정보는 마스킹한다.

## 4. Codex CLI 실행 템플릿

### 4.1 코드 리뷰 기본: `codex review`

```bash
# 현재 워킹트리(스테이징/언스테이징/신규 파일 포함) 리뷰
codex review --uncommitted "보안/성능/회귀 위험 중심으로 리뷰해줘"

# 기준 브랜치 대비 리뷰
codex review --base main "아키텍처 위반과 테스트 누락을 우선 점검해줘"

# 특정 커밋 리뷰
codex review --commit <sha> "이 커밋의 정합성 리스크를 점검해줘"
```

### 4.2 파일/영역 지정 심화 리뷰: `codex exec`

```bash
codex exec "@apps/commerce-api/src/... @modules/jpa/src/... 주문 생성 변경의 보안/정합성/성능 리스크를 우선 리뷰해줘"
```

### 4.3 계획 검증: `codex exec`

```bash
codex exec "다음 구현 계획의 타당성, 잠재적 리스크, 테스트 전략을 검토해줘: [계획 상세]"
```

## 5. 결과 반영 규칙 (중요)

1. Codex 피드백은 원문 의미를 유지해 사용자에게 투명하게 전달한다.
2. 피드백은 `수용 / 기각 / 보류`로 분류하고 근거를 남긴다.
3. "중요 지적사항"도 맹목 반영하지 말고 코드/테스트 근거로 검증한다.
4. 반영 후 최소 1개 이상 검증 명령(테스트/린트)을 실행한다.
5. 보안/정합성 관련 수정을 했으면 재검증을 수행한다.

예시 보고 포맷:

```text
> Codex:
> - 보안: ...
> - 성능: ...

반영 결정:
- 수용: ... (근거)
- 기각: ... (근거)
- 보류: ... (추가 확인 항목)
```

## 6. 실패/예외 처리

- `codex` 명령 실패 시: 프롬프트를 축약해 1회 재시도한다.
- 재시도도 실패하면: 자체 리뷰 체크리스트(보안/성능/정합성/테스트)로 대체 검증 후 사용자에게 실패 원인과 대응을 보고한다.
- 타임아웃/과도한 응답 발생 시: 범위를 파일 단위로 쪼개 재실행한다.
- 네트워크/인증 이슈 시: 오류 메시지를 포함해 상황을 즉시 공유하고 로컬 검증 결과를 먼저 제공한다.

## 7. 워크플로우 예시

```text
1. 사용자: "캠페인 생성 기능 구현해줘"
2. Claude: 계획 수립
3. Claude: codex exec로 계획 검증, 리스크 반영
4. Claude: 코드 구현 + 테스트 실행
5. Claude: codex review --uncommitted로 변경분 리뷰
6. Claude: 피드백 수용/기각 근거 정리 후 개선
7. Claude: 재테스트 + 필요 시 재검증
8. Claude: 최종 결과 + Codex 피드백 요약 + 반영 근거 보고
```
